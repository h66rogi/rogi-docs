# 실시간 채팅

`wss://data-api.rogi.chat/v1/chat/stream`은 표준 WebSocket과 JSON 메시지를 사용합니다.
Socket.IO 프로토콜은 첫 버전의 계약에 포함되지 않습니다.

접속 직후 서버는 버전, 방송 상태와 cursor 보존 범위를 보냅니다. 이어서
`broadcast.status`, `chat.message`, `chat.gap`, `heartbeat`, `error` 이벤트를 보냅니다.

```json
{
  "type": "hello",
  "version": "v1",
  "serverTime": "2026-09-23T08:00:00Z",
  "broadcastState": "live",
  "broadcastId": "example-broadcast-id",
  "title": "방송 제목",
  "currentCursor": "opaque-cursor",
  "earliestCursor": "opaque-cursor",
  "cursorRetention": "up to 24 hours and 10000 stream entries"
}
```

```json
{
  "type": "chat.message",
  "eventId": "example-event-id",
  "cursor": "opaque-reconnect-cursor",
  "receivedAt": "2026-09-23T08:00:05Z",
  "user": {"displayName": "시청자"},
  "message": "안녕하세요"
}
```

예시는 합성 데이터입니다. 새 연결에 cursor가 없으면 현재 시점부터 전달합니다. 이어받으려면 마지막
`chat.message.cursor`를 URL의 `?cursor=`에 넣습니다. Redis의 최근 범위(최대 24시간, 10,000건)를
벗어나거나 stream generation이 바뀌면 서버가 `chat.gap`을 보냅니다. 이 경우 과거 조회 API로
복구 가능한지 확인하세요. 연결은 최대 2시간이며 heartbeat는 약 20초마다 전달됩니다.

`GET /v1/chats/recent?cursor=&limit=`으로 같은 Redis 범위를 HTTP로 조회할 수도 있습니다.
응답은 `messages`, `nextCursor`, `retention`이며 기본 50건, 최대 100건입니다. 만료된 cursor는
`409 cursor_expired`입니다. 실시간 메시지에는 영구 archive의 `sessionId`나 가명 사용자 ID가
포함되지 않습니다.
